## Deviations from the spec
- Slope grid: `analyzeVision` already uses a 7-point grid S_GRID [3..20] with a shared slope, so QUEST+ uses that same grid per colour (uniform prior) instead of a new 5-point grid. A 5-point and a fixed-slope variant gave about the same precision (tested in scratch).
- Prior centre is `opts.start[c]` / `VT.x0` exactly as specified. Note `visionStart` supplies x75+0.1 while the grid parameter is the 50% point, an offset of about 0.1; it is small against the SD of 0.5. Prior SD can be overridden with `opts.priorSd`.

## Measured numbers (simulated observer, slope 8, lapse 0.02, truth yellow -1.3 / red -0.9 / purple -1.0)
- 30 seeds, median profile-likelihood CI width from `analyzeVision`: QUEST+ 12/colour 0.18 vs old staircase 20/colour 0.15 (inline rule, start -0.5, steps -0.05/+0.15, doubled before 2 reversals).
- 60 seeds, scratch run: median CI width 0.15 vs 0.14; mean 0.208 vs 0.183; RMSE of x75 against truth 0.288 vs 0.202.
- So 12 QUEST+ trials are about 1.4x worse in RMSE than 20 staircase trials. That is roughly what the trial count alone predicts (sqrt(20/12) = 1.29), so per-trial efficiency is about equal, not better. The staircase here is helped by an observer that matches the fitted model exactly. The "about 40% fewer trials at the same precision" claim is not supported by this simulation. At 12 per colour, expect roughly 0.2 log10 wider uncertainty (or use `perColor` of about 16 to match).
