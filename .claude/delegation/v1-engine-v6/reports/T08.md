## Deviations from the spec
- DPI card text says the card's LONG edge (8.56 cm is the long edge; the short edge is 5.4 cm).
- Swipes (DPI, pad, reach) use hold-button-and-release to mark start and end, for all three, including reach. DPI counts = sum |dx|; pad/reach use net |sum dx|, converted with the measured counts per cm.
- Measured counts per cm are used for all later cm values whenever the DPI check ran (even if flagged inconsistent or acceleration-suspect, with a warning shown); only a skipped check falls back to stated DPI / 2.54.
- Done card has a Continue button; `onDone` fires on Continue, then the component removes its DOM and exits pointer lock. `controller.abort()` also calls `onCancel("abort")`.
- Thorough mode: second `schedule` pass with seed+1, ids/order/block renumbered to continue. Adaptive extra block is counted in "Block k of N" when `opts.density` is given.
- Trial view is reset to yaw 0 / pitch 0 at each trial start; a 0.7 to 1.2 s hold (crosshair only) precedes each target.
- Block card auto-starts after a 3 s countdown (Enter or "Start now" skips).
- Input uses `pointerrawupdate` when available (duplicate `mousemove` suppressed while raw events flow), else `mousemove`. Not testable headless; real pointer lock, unadjustedMovement and raw events are untested in a real browser here.
