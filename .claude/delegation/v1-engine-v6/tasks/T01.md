# T01: Simulated player that produces mouse trajectories

**Agent:** executor-sonnet

## Goal
Create `sim/player.js`: a seeded virtual player with known ("truth") motor constants who performs aim-test trials and returns realistic mouse trajectories. It is the ground truth for testing the aim-test analysis (aim.js) and the engine's validation scorecard.

## Background
valoSens recommends a Valorant mouse sensitivity (cm/360). Engine v6 adds an in-browser aim test. To check that the test's analysis recovers a player's real constants, we need a simulated player whose constants we know. Read `CONTRACTS.md` in this folder first: it defines the trajectory, trial spec and truth formats you must produce. `PLAN.md` gives background.

## Interface
```js
var Sim = require("../sim/player.js");          // browser: window.ValoSim
Sim.TRUTH_DEFAULTS   // { sigma0: 0.02, k: 0.05, tSub: 0.15, vPeak: 150, reachCm: 8, tLift: 0.3, padCm: 38, countsPerCm: 314.96, rt: 0.2 }
Sim.TRUTH_RANGES     // { key: [lo, hi] } plausible ranges (use: sigma0 [0.01,0.04], k [0.02,0.1], tSub [0.1,0.25], vPeak [100,250], reachCm [3,15], tLift [0.2,0.5], padCm [20,85], rt [0.16,0.28])
Sim.randomTruth(seed) -> truth           // log-uniform draw within TRUTH_RANGES (countsPerCm fixed at 314.96)
Sim.createPlayer({ seed, truth }) -> player   // truth merged over TRUTH_DEFAULTS
player.truth
player.run(spec) -> { traj, summary }    // spec per CONTRACTS "Trial spec"; traj per CONTRACTS "Trajectory"
   // summary = { time, hit, nSub, lifts, peakCmS, endErrDeg } (the sim's own ground truth for this trial)
```

## Model the sim must implement (decisions already made)
Work in mouse-space cm. Required travel `a = |angleDeg| / 360 * spec.cm` (sign gives direction). Target half-width in cm `wCm = spec.targetDeg / 2 / 360 * spec.cm`.
1. **Reaction:** no movement for `rt` (± 10% gaussian jitter).
2. **Primary submovement:** minimum-jerk profile from current position toward the target, amplitude `A` (remaining distance), duration `D = max(0.12, 1.875 * A / vPeak_eff)` where `vPeak_eff = vPeak` if `A <= reachCm` else `vPeak * 1.0` but add a joint-switch delay of 0.06 s before it. Endpoint error ~ Normal(0, sqrt(sigma0² + (k·A)²)) along the movement axis, Normal(0, sigma0) vertical.
3. **Pad and lifts:** the hand starts at a uniform random offset within ±50% of pad half-width from the pad centre (`padCm` is usable width). If the planned movement would take the hand past the pad edge, the movement stops at the edge, then there is a **lift**: no samples for `tLift` (± 15% jitter, but at least 0.06 s), the hand is re-centred to the opposite side at 85% of the half-width, and the remaining distance continues as a new submovement. Count lifts.
4. **Corrections:** after each submovement, if |error| > wCm, wait `tSub * 0.4` (visual processing) and make a corrective submovement of duration `max(0.08, tSub)` with endpoint noise `sqrt(sigma0² + (k·|err|)²)`. Up to 8 corrections, then a timeout (4 s total cap; `hit:false`).
5. **Click:** when within wCm, click after 0.03 s → `done`, `clicks:[{t, hit:true}]`. Model a premature-click miss with probability 0.1 when the last correction was within 2·wCm but outside wCm (add `{t, hit:false}` before continuing).
6. **Track task:** target yaw moves at `strafeDegS` with reversals at random 0.4–0.9 s. The hand follows with a 0.15 s visual delay, a velocity error of 10% of target speed (Gaussian, renewed every 0.15 s), plus position noise `trackFloor = sigma0 * 1.25` (cm, Gaussian random walk smoothed over 50 ms). Run for `durationS` (default 2.5). Record clicks every 0.1 s with hit = |crosshair − target| < targetDeg/2 in degrees. `summary.time = 0.25 / max(onTargetFraction, 0.05)` capped at 10.
7. Samples at 1000 Hz (`t` step 0.001) except during lift gaps. `x`, `y` cumulative cm. Use the trial seed `hash(player seed, spec.id)` so the same spec always gives the same trajectory.

Keep the code readable: one function per phase, comments citing the rule numbers above.

## Steps
1. Implement `sim/player.js` per the interface and model above.
2. Write `test/sim.test.js` (same tiny harness style as `test/model.test.js`: `t(name, fn)` printing ok/FAIL and a final "N passed, M failed" line, exit code 1 on failure) covering:
   - determinism: same seed + spec → identical traj.
   - trajectory format: arrays equal length, `t` ascending, last x within target ±wCm on hits.
   - lifts: a 180° turn at cm=80 with padCm=25 produces ≥1 lift and a gap ≥ 0.06 s in `t`; a 2° micro at cm=30 produces 0 lifts.
   - noise scaling: over 200 micro trials, the SD of the first submovement endpoint error (from the sim's internals or summary) is within 25% of `sqrt(sigma0²+(k·A)²)`.
   - higher sigma0 → more corrections (mean nSub) on micro trials at a fast sensitivity (cm=15).
   - track: onTarget fraction lower for a player with sigma0=0.04 than 0.01 at cm=15.
3. Run the acceptance commands.
