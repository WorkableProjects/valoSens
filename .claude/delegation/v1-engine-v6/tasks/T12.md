## Changes (decisions already made)

### 1. Sensitivity tab
- **Remove** the "Distribution" panel (`distChart`). The **bell chart becomes the first, full-width panel.**
- **X axis:** sensitivity at the player's DPI (convert from s800: `sens = s800 · 800 / dpi`). Ticks every 0.1 at 800 DPI equivalent; label with the DPI.
- **Bell:** the population curve N(R.bell.mean, R.bell.sd) in s800 units, drawn as today, with the mean (0.30 @ 800) marked "average player".
- **Overlay:**
  - shaded band for the 80% interval (`R.bell.ci80s800`);
  - darker band for the 50% interval (convert `R.posterior.ci50` cm → s800 with `M.s800FromCm`);
  - a marker for the result (`R.cm`);
  - a marker for the current setting, if any;
  - staged-plan markers (keep the existing target/staged-step marker logic from the last commit, `dba0e07`).
- **Caption under the chart:** "80% likely between **X** and **Y** (sens at N DPI). Higher than P% of players." Use `R.bell.percentile` for the player's result.
- Keep the hover tooltip and the draw-in animation. Keep `id="bellChart"`, `#bellPct` and `path.ln` so the existing assertions still work, or update them in the e2e.

### 2. "Why this number" (replaces "What moved you")
A horizontal waterfall from `R.posterior.waterfall`:
- **Start:** "Average player: 0.30". This is the `population` step; show it in sens at the player's DPI.
- **One bar per step** (region, agents, physics "Your setup", measured "Your aim test"):
  - signed change in sens: s800 of `exp(ln_before + dLn)` minus s800 of `exp(ln_before)`, converted to the DPI;
  - a label, and a basis chip (research / model / measured).
- **End:** "Your result", the median. If progression holds the player at the current setting, add a note: "kept at your current setting".
- Bars animate in sequence (stagger), respecting `prefers-reduced-motion`.
- Keep class `.shift` on rows, or update the e2e.

### 3. Confidence
Replace the heuristic badge text. The badge shows `R.confidence.label` (HIGH / MED / L–M / LOW). The caption is:
- posterior: "From players like you and your setup. The aim test narrows this."
- measured: "From your aim test, players like you and your setup combined."

The gauge uses the 80% interval. Summary row "Near-optimal" becomes **"Likely range"**, `R.lo`–`R.hi` (50%), in sens at the user's DPI (also show cm/360 small).

### 4. Aim test section
Shown when `S.aim` exists or `R.mode === "measured"`. It goes in the Sensitivity tab under the waterfall, with the title "Your aim test".
- **DPI check:** effective DPI vs stated, with a warning if `accelSuspect` or not consistent.
- **Pad width and reach measured** (cm).
- **Measured constants:** `R.personalUsed`, as friendly labels:
  - hand steadiness (sigma0, in mm)
  - correction time (ms)
  - peak speed (cm/s)
  - lift time (ms)
- **Small chart:** mean trial time per tested sensitivity. Compute it from `S.aim.trials` grouped by cm, warmups excluded, as means ± SE. Mark the measured best (`R.measured.fittedOptimum`).
- **Status line:** whether the curve was clear (`R.measured.validation.curveBeatsFlat`). If not: "No clear difference between tested settings: the result leans on your setup and players like you." Also show `R.measured.warnings`.

### 5. Model tab
Add a "How the engine combined the evidence" table: population, your setup (weight %), aim test. Each row has a centre (sens at DPI) and an 80% width. Keep the cost chart and the existing text, with stale v5 wording updated (no "near-optimal range" as the main result; mention "posterior" in plain words: "most likely range").

### 6. Test plan tab
If `R.anchor` has `stages > 1`, show a timeline: stage 1 now, then stage k after about 3 sessions each, listing the sens values. Add **"Add retest reminder"**, which downloads a `.ics` file (local Blob, no network) with an event 7 days later titled "valoSens retest", whose description says to import the results file.
