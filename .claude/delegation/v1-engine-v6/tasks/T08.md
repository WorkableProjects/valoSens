## Goal
Build the in-browser sensitivity aim test as a self-contained UI component, `ui/aimtest.js` + `ui/aimtest.css`, driven by `aim.js`. It runs the calibration checks (DPI card swipe, pad width, reach), then the trial blocks. It records raw mouse movement and hands back trial records plus checks to a callback. ## Interface (decisions already made)
```js
// global, defined by ui/aimtest.js
AimTest.start(host /* HTMLElement */, opts, onDone, onCancel) -> controller { abort() }
opts = {
  dpi: number,              // stated DPI (required)
  centreCm: number,         // prior median cm/360 from the engine (levels are placed around it)
  mix: { micro, flick, turn, track },   // trials per level, default { micro: 8, flick: 6, turn: 4, track: 2 }
  levels: 5, spanOct: 0.6, seed: number, session: "cur",
  thorough: false,          // true = 2 passes (12 min) instead of 1 (6 min)
  density: function (cm) -> number,     // optional: posterior density for adaptive extra blocks (ValoAim.nextLevel)
  source: null              // TEST HOOK, see below
}
onDone({ trials /* toTrial records, warmups excluded */, records /* [{spec, feat}] non-warmup */, checks: { dpi, pad, reach },
         personal /* estimatePersonal(records, checks) */, rawInput: boolean, frameMs: number, droppedFrames: number,
         trajectories: [ downsampled traj per trial: t/x/y arrays at <= 120 Hz ] })
onCancel(reason)
```

### Flow inside the component
1. **Intro card.** What will happen, about 6 minutes, keep your normal grip and in-game posture, use the mouse pad you play on. Esc pauses at any time. Start button.
2. **Pointer lock.** `el.requestPointerLock({ unadjustedMovement: true })`. If that rejects or throws (Firefox/Safari), call `requestPointerLock()` without options and set `rawInput:false`. Show a small note that OS acceleration may affect results, and that the DPI check will flag it.
3. **DPI check.**
   - Ask for a bank card or ruler: "place the card's short edge... move the mouse exactly 8.56 cm left to right along it, click".
   - Three repeats at different speeds ("slowly", "normal", "fast").
   - Sum |movementX| counts between press and release, and the time.
   - Feed `ValoAim.dpiCheck([{counts, cm: 8.56, durS}], dpi)`.
   - Show the result: effective DPI, and a warning if not consistent or if accelSuspect. Allow a "skip" option (then use stated DPI / 2.54).
4. **Pad width.** "Lift and place the mouse at the left edge of your pad, hold the button, drag to the right edge, release", 2 repeats. `ValoAim.padCheck`.
5. **Reach.** "With your elbow and forearm still, swipe right as far as feels comfortable, release", 3 repeats. `ValoAim.reachCheck`.
6. **Trials.**
   - `levels = ValoAim.levelsAround(opts.centreCm, opts.levels, opts.spanOct)`, then `blocks = ValoAim.schedule(...)`.
   - For each block, show a "Block k of N" card with a short countdown, then run its specs.
   - Render the scene on a full-window `<canvas>` with a simple horizon/grid backdrop. Draw the target as a head-size circle at `ValoAim.screenX(targetYaw − viewYaw, W)` and `screenY`. The crosshair is fixed at the centre.
   - **View rotation:** `viewYaw += movementX / countsPerCm * 360 / cm` (cm = the block's cm/360). Pitch likewise with −movementY. Clamp pitch to ±60.
   - **Target behaviour by task:**
     - Turn: the target is placed at the yaw offset. When off-screen, show an edge arrow pointing the short way.
     - Track: the target moves per spec (strafe with reversals, generated from the spec seed).
   - **Click:** hit if the crosshair is within targetDeg/2 of the target centre (2D angular distance). Static trials end on a hit, or at 4 s.
   - **Recorder (one rule, decided):** Push a sample for every mouse event: accumulate movementX/Y, convert to cm (counts / countsPerCm), and timestamp with the event's `timeStamp`, relative to trial start. On every animation frame with no mouse event, push a zero-movement sample **only if** one of these holds:
     (a) the first movement of the trial hasn't happened yet (reaction phase), or
     (b) the crosshair is within 2 × targetDeg of the target centre (aiming pause), or
     (c) the trial is a track trial.
     Otherwise push nothing, so a lift away from the target appears as a gap of 60 ms or more, which is the lift signal `ValoAim.features` uses. A browser can't tell a lifted mouse from a stationary one, so this is the decided heuristic: pauses far from the target count as lifts. Explain this in a code comment.
   - Build `traj` per CONTRACTS, then `feat = ValoAim.features(traj, spec)` and `ValoAim.toTrial(spec, feat)`.
   - **Adaptive extra block** (only if `opts.density` is given): after the scheduled blocks, run one extra block at `ValoAim.nextLevel(levels, counts, opts.density)`.
7. **Pause and cancel.** Esc or a lost pointer lock pauses with a card offering Resume or Quit. Quit calls `onCancel("user")`. The trial in progress is discarded and repeated on resume.
8. **Frame timing.** Measure frame intervals. Count dropped frames per trial (interval > 1.5 × median) and set `trial.droppedFrames`.
9. **Done card,** then `onDone(...)`. Downsample trajectories to ≤ 120 Hz for `trajectories`.

### Accessibility and motion
- Every card is keyboard-operable, with focus on the primary button.
- Text uses the existing type scale.
- `prefers-reduced-motion` disables the countdown animation (the trials themselves are inherently motion).

### Test hook (decisions already made)
- `opts.source`: an object `{ attach(onMove, onDown, onUp) }`. When given, the component does NOT request pointer lock or listen to mouse events. The source calls `onMove(dx, dy, tMs)`, `onDown(tMs)` and `onUp(tMs)` with synthetic counts and timestamps.
- `aimtest.html` reads `?auto=1` and then attaches a scripted source. The scripted bot reads the current target angle via `AimTest._debug()`, which exposes `{ viewYaw, viewPitch, target, spec, phase }`, and moves toward it with a minimum-jerk profile plus noise.
- In auto mode, `aimtest.html` uses `mix { micro: 2, flick: 2, turn: 1, track: 1 }` and `levels: 3`. On done it writes `JSON.stringify(result)` into `<pre id="out">`.
