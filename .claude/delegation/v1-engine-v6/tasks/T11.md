# T11: Validation scorecard on simulated players

**Agent:** executor-sonnet

## Goal
`test/scorecard.js` answers the release question: **how close does valoSens get to a player's true best sensitivity, with and without the aim test, and are its intervals honest?** It is the release gate (docs/V1_ENGINE_V6_PLAN.md §4 V1).

## Owns
- `test/scorecard.js` (create)
- `test/scorecard.md` (create: the latest results table, written by the script with `--write`)

## Read-only context
- `CONTRACTS.md` (this folder), including the "Engine v6 input/output" section at the end
- `sim/player.js` (`createPlayer`, `randomTruth`, `run(spec)`), `aim.js` (`levelsAround`, `schedule`, `features`, `toTrial`, `estimatePersonal`, `padCheck`, `reachCheck`)
- `model.js` `recommend()`; `test/model.test.js` (harness style)

## Method (decisions already made)
For each virtual player i (seeded):
1. `truth = Sim.randomTruth(seed)`, `player = Sim.createPlayer({ seed, truth })`.
2. **Questionnaire answers** derived from the truth, as a player would answer:
   - `pad = round(truth.padCm + 6.5)` (usable width + mouse width);
   - `limb`: "wrist" if reachCm < 5, "wf" if < 8, "forearm" if < 12, else "arm";
   - `experience`: "comp" if sigma0 < 0.015, "exp" if < 0.022, "mid" if < 0.03, else "new";
   - `role` "f", `weapon` "rifle", `dpi` 800.
3. **True optimum (independent of model.js):**
   - Evaluate the sim player's expected cost at 13 log-spaced cm values from 12 to 120.
   - Cost at a cm = mean over N_true = 60 trials per task of the trial time. Use `run(spec)` with specs from `ValoAim.schedule` geometry; build specs directly with the same task geometry. Weight tasks by the default mix: micro 0.34, flick 0.34, turn 0.17, track 0.15.
   - Fit a quadratic in log2(cm) around the 5 best points, and take its minimum as `cTrue` (clamped to the evaluated range).
   - Cache the truths and optima in `test/.scorecard-cache.json`. The cache is ignored by git: add `test/.scorecard-cache.json` to a `.gitignore` entry **in your report**, don't edit .gitignore.
4. **Arms:**
   - **A prior:** `recommend(answers, { priorOnly: true }).cm`
   - **B questionnaire:** `recommend(answers).cm`
   - **C questionnaire + aim test (6 min):**
     - Run the default aim-test design on the sim: `levelsAround(B.cm, 5, 0.6)` and a schedule with perLevel `{ micro: 8, flick: 6, turn: 4, track: 2 }` and warmup 2.
     - Compute `features → toTrial` for every spec. Use `padCheck`/`reachCheck` with values `truth.padCm`/`truth.reachCm` × (1 + N(0, 0.05)), 2 and 3 swipes.
     - `personal = estimatePersonal(records, { pad, reach })`.
     - Result: `recommend({ ...answers, calibration: { trials }, personal }).cm`.
     - If recommend throws "Not enough calibration trials", record the arm as failed for that player.
   - **D thorough (12 min):** like C with two passes (two sessions "s1" and "s2", different seeds).
5. **Metrics per arm:**
   - |log2(c/cTrue)| (octaves): median, mean, 90th percentile;
   - 80% interval coverage: the share of players whose cTrue lies in `R.posterior.ci80` (A and B use their own posterior; C and D too);
   - 50% coverage, from `ci50`;
   - failure count.
6. **Output:** a table to stdout. With `--write`, also write `test/scorecard.md` with the table, n, seeds and date.
7. **CLI:**
   - `node test/scorecard.js` runs fast mode: n = 60 players, N_true = 30.
   - `--full` runs n = 400, N_true = 60.
   - `--gate` exits 1 unless arm C's median error ≤ 0.15 octave **and** its 80% coverage is within [0.70, 0.90].
   - Print timing.
