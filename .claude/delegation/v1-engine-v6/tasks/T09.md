# T09: QUEST+ adaptive placement for the highlight vision test

**Agent:** executor-sonnet
**Depends on:** none
**Wave:** 2

## Goal
Replace the weighted up-down staircase in `xhair.js` `visionRun()` with QUEST+ (Watson 2017, Journal of Vision 17(3):10). It chooses each trial's outline strength to minimise the expected entropy of the posterior over (threshold, slope). The goal is the same threshold precision in about 40% fewer trials. The public API and trial format stay the same, so the UI (`ui/tests.js`) and results files (`session.js`) keep working.

## Decisions already made
- **Psychometric function:** the same one `analyzeVision` uses, `p = guess + (1 − guess − lapse)·F(x; threshold, slope)`, on x = log10 opacity.
- **Parameter grid:**
  - threshold: x from −2.5 to 0 in 0.05 steps;
  - slope: the set analyzeVision assumes (if it uses one fixed shared slope, use a 5-point grid around it, ×0.5 to ×2, log-spaced);
  - stimulus x: −2.5 to 0 in 0.05 steps.
- **Prior per colour:** Gaussian on threshold, centred on `opts.start[color]` if given, else `VT.x0`, SD 0.5 log10. Uniform on slope.
- **One QUEST+ posterior per colour,** interleaved in the same queue order as now. Catch trials stay the same.
- **Trials per colour:** `VT.perColor` becomes **12** (from 20), so the whole test drops from ~67 to ~43 trials. Keep `opts.perColor` override.
- `nextTrial()` still returns `{ idx, color, hex, catchTrial, x, alpha, exposureMs, scene, ... }` with the same fields. `record(t, { answer, shownMs, dropped })` is unchanged. The trial objects stored in `trials` keep the same fields.
- **Dropped frames:** dropped trials don't update the posterior and are repeated (keep the current behaviour).
- `analyzeVision` is unchanged in behaviour by default.
- Export `questPlus` helpers for tests as `X._quest = { create, update, next, mean }`.
